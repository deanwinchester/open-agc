# ARM64 deb CI 自动构建 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Release CI 同时产出 Linux `amd64` 与 `arm64` 两个 deb 安装包，解决 UOS/银河麒麟（ARM64）安装时「软件包架构不匹配」的问题。

**Architecture:** 在现有 `.github/workflows/docker-release.yml` 的 `linux-deb` job 上把 matrix 从单 `amd64` 扩成 `amd64` + `arm64`；`arm64` 使用 GitHub ARM64 runner（`ubuntu-22.04-arm`）原生运行 PyInstaller，避免交叉编译。deb 组装与上传逻辑不变，仅按 `matrix.arch` 区分 `Architecture` 与产物文件名。

**Tech Stack:** GitHub Actions, PyInstaller, dpkg-deb, bash, Python (测试)

## Global Constraints

- 不修改现有 Windows / macOS / Docker 构建 job。
- deb 包名 `open-agc`，安装路径 `/opt/open-agc/`，桌面文件 `/usr/share/applications/open-agc.desktop`。
- `DEBIAN/control` 的 `Depends` 保持 `libwebkit2gtk-4.0-37, libgtk-3-0`。
- `amd64` 继续跑在 `ubuntu-22.04`；`arm64` 跑在 `ubuntu-22.04-arm`。
- 产物命名：`Open-AGC-<VERSION>-Linux-<ARCH>.deb`（`<ARCH>` 为 `amd64` 或 `arm64`）。
- 版本号从 `VERSION` 文件读取。

### Task 1: 为 linux-deb matrix 添加 CI 结构测试

**Files:**
- Create: `tests/test_release_workflow.py`

**Interfaces:**
- Consumes: `.github/workflows/docker-release.yml`
- Produces: 一个可重复运行的 pytest 测试，验证 `linux-deb` job 的 matrix 包含 `amd64`/`arm64` 且 `runs-on` 使用 `${{ matrix.runner }}`

- [ ] **Step 1: 编写失败测试**

```python
# tests/test_release_workflow.py
import os
import yaml

WORKFLOW = os.path.join(
    os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
    ".github", "workflows", "docker-release.yml",
)


def _linux_deb_job():
    with open(WORKFLOW, "r", encoding="utf-8") as f:
        data = yaml.safe_load(f)
    return data["jobs"]["linux-deb"]


def test_linux_deb_matrix_includes_amd64_and_arm64():
    job = _linux_deb_job()
    include = job["strategy"]["matrix"]["include"]
    arches = {entry["arch"] for entry in include}
    assert arches == {"amd64", "arm64"}


def test_linux_deb_uses_matrix_runner():
    job = _linux_deb_job()
    assert job["runs-on"] == "${{ matrix.runner }}"


def test_linux_deb_matrix_defines_runner_per_arch():
    job = _linux_deb_job()
    include = job["strategy"]["matrix"]["include"]
    runners = {entry["arch"]: entry["runner"] for entry in include}
    assert runners["amd64"] == "ubuntu-22.04"
    assert runners["arm64"] == "ubuntu-22.04-arm"
```

- [ ] **Step 2: 运行测试确认失败**

Run: `python -m pytest tests/test_release_workflow.py -v`
Expected: FAIL（`include` 不存在或 `arch` 只有 `amd64`）

### Task 2: 扩展 linux-deb job 支持 arm64 构建

**Files:**
- Modify: `.github/workflows/docker-release.yml:218-229`

**Interfaces:**
- Consumes: Task 1 的测试
- Produces: `linux-deb` job 的 matrix 同时包含 `amd64`（`ubuntu-22.04`）与 `arm64`（`ubuntu-22.04-arm`），`runs-on` 为 `${{ matrix.runner }}`

- [ ] **Step 1: 修改 workflow matrix 与 runs-on**

```yaml
  linux-deb:
    needs: create-release
    # 固定在 ubuntu-22.04：jammy 提供 libwebkit2gtk-4.0-37，与 deb 的 Depends 目标环境一致
    runs-on: ${{ matrix.runner }}
    permissions:
      contents: write
    strategy:
      matrix:
        include:
          - arch: amd64
            runner: ubuntu-22.04
          - arch: arm64
            runner: ubuntu-22.04-arm
```

- [ ] **Step 2: 运行测试确认通过**

Run: `python -m pytest tests/test_release_workflow.py -v`
Expected: PASS（3 个测试全部通过）
